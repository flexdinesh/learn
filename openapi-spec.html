    Tradeoffs
    Three choices that matter
    
            
    Choose according to ownership and release constraints.
    
          
    
          
    
            
    
              
    Design-first vs code-first
    
              
    Design-first enables early review, mocks, and parallel client work.
    
              
    It needs conformance tests to stop YAML and code drifting.
    
              
    Generated code-first output still needs review as a public contract.
    
            
    
            
    
              
    Local vs shared schemas
    
              
    Local components are simple and evolve with one server.
    
              
    Cross-server sharing adds owners, versions, and support windows.
    
              
    Share meaning—not ORM entities that happen to look alike.
    
            
    
            
    
              
    Monorepo vs registry
    
              
    A monorepo makes atomic edits and relative refs easy.
    
              
    A registry costs more but gives independent repos immutable pins.
    
              
    Both can publish the same consumer-facing bundle.
    
            
    
          
    
        
    

        
    
          
    
            
    Check the model
    Predict the next design
    
            
    Answer before opening.
    
          
    
          
    
            A second route needs the same Book response. What changes?
            
    Move Book into components.schemas.Book and reference it from both operations. It remains local to the single server.
    
          
    
          
    
            Reviews becomes a separate server. Should it import Catalog’s full Book model?
            
    Usually no. Publish a deliberately small BookSummary only if both services truly share its semantics. Keep richer models local.
    
          
    
          
    
            What crosses the network at runtime: the OpenAPI file or Book JSON?
            
    Book JSON. The OpenAPI description is normally consumed by humans and tools before or around runtime.
    
          
    
          
    
            Does a central registry make one team the owner of all operations?
            
    No. It can centralise discovery and distribution while service teams keep operation ownership. Shared models need an explicit owner.
